# じぶん会議 test版 World-class UI/UX 設計書

## 0. この文書の目的

この文書は、じぶん会議 test版を「雰囲気の良いプロトタイプ」から「世界クオリティの内面会議アプリ」へ高めるための設計基準です。

Phase 6Aでは、実装を急がず、まず以下を固定します。

- 目指す体験
- デザイン哲学
- UI/UX原則
- 各エージェントのUI人格
- 画面ごとの磨き込み方針
- モーション方針
- スマホ優先ルール
- やらないこと
- Phase 6B以降の順番

## 1. 現在地

Phase 0〜5で、test版は以下の状態まで来ています。

- UI方針が整理されている
- スプラッシュ、背景、入力欄、空チャットが強化済み
- エージェントバーが「声のデッキ」になっている
- `委ねる` 体験が追加されている
- 会議録と星座風関係性マップがある
- スマホsafe-areaやモーダル表示が調整済み
- Cloudflare手動デプロイ手順と公開前チェックがある

ここから先は、単に装飾を増やすのではなく、全体をより一貫した体験として磨き込みます。

## 2. 目指す完成像

> 静かな会議室に、自分の中の声が灯る。  
> 触れるほど、自分の内側が少し整理される。  
> 美しいのに、迷わない。  
> 神秘的なのに、使いやすい。

じぶん会議 test版は、ただのチャットUIではなく「内面の会議室」です。

完成時に感じさせたい印象:

- 余白がある
- 触り心地が軽い
- それぞれの声が生きている
- 情報が過剰ではない
- 会議録として戻ってきたくなる
- スマホで毎日開ける
- 一目で「普通のAIチャットではない」と分かる

## 3. デザイン哲学

### 3.1 美しさは静けさから生まれる

派手な演出より、余白・間・呼吸感を優先します。

画面は叫ばない。  
必要なときだけ、静かに光る。

### 3.2 UIは人格の衣装である

各エージェントの違いは、説明文だけでなく、形・光・余白・動き・文言から伝える必要があります。

色だけでキャラ分けしない。  
その声らしい「場」をUIにも持たせます。

### 3.3 情報を増やすより、迷いを減らす

世界クオリティとは、機能が多いことではありません。

- 何を押せばいいか分かる
- 今どこにいるか分かる
- 次に何ができるか分かる
- でも押しつけられない

この状態を目指します。

### 3.4 深さは段階的に開く

初見ではシンプル。  
長く使う人には深く見える。

そのために、情報は一度に全開示せず、以下の段階で見せます。

1. 最初に見える短い説明
2. タップ/長押しで開くプロフィール
3. 会話後に見えてくる関係性
4. 会議録として蓄積される文脈

## 4. UX原則

### 4.1 最初の10秒で伝えること

初回体験では、以下だけが伝わればよいです。

- これは自分の中の複数の声と話すアプリである
- 何を書いてもいい
- 声を選んでも、委ねてもいい
- 会話は会議録として残る

### 4.2 毎回の利用で迷わせないこと

毎回の利用では、以下を明確にします。

- 今どの会議を開いているか
- 今どの声に聞いているか
- どこに書けばいいか
- 他の声を聞くにはどうするか
- 会議録をどこで見返すか

### 4.3 スマホ片手利用を前提にする

じぶん会議 test版は、スマホでふと開けることが重要です。

優先すること:

- 下部入力欄の安定
- 親指で押しやすいボタン
- 横スクロールの軽さ
- モーダルの閉じやすさ
- キーボード表示時の破綻回避

## 5. デザインシステム方針

Phase 6B以降で、現在のPhase別CSSを整理し、以下の共通ルールを作ります。

### 5.1 色トークン

主な色階層:

- `base`: 背景
- `surface`: カードやパネル
- `elevated`: 浮いている面
- `border`: 境界線
- `text-primary`: 主文
- `text-secondary`: 補助文
- `text-muted`: 薄い説明
- `accent`: 現在の主要な光

### 5.2 余白スケール

余白は以下の感覚で揃えます。

- 4px: 微細な距離
- 8px: 小さなまとまり
- 12px: ボタン内余白
- 16px: スマホ標準余白
- 24px: セクション余白
- 32px: 大きな空気
- 48px: 画面の呼吸

### 5.3 角丸階層

- 12px: 小ボタン
- 16px: 小カード
- 22px: 入力欄
- 28px: モーダル/大カード
- 32px以上: 世界観を持つ大きな器

### 5.4 影とガラス感

影は強くしすぎません。

- 背景に沈む影
- 浮いているカードの影
- 選択中だけ少し光る影

ガラス感は「透明にしすぎて読みにくい」を避けます。

### 5.5 タイポグラフィ

日本語を主役にします。

- 見出し: 少し余白を持った文字間
- 本文: 読みやすい行間
- 補助文: 小さくても読める濃度
- エージェント名: 短く、記号的に見える扱い

## 6. 主要コンポーネント再設計方針

Phase 6Bで、以下を整理します。

### 6.1 Header

役割:

- 現在の会議名
- メニュー
- テーマ切替
- 関係性マップ

改善方針:

- 情報を詰め込みすぎない
- 会議名が長くても破綻しない
- アイコンボタンの押しやすさを担保

### 6.2 WelcomePanel

役割:

- 最初の問いの入口
- 何を書けばいいかの不安を消す

改善方針:

- 「何について掘り下げますか？」から、より会議室らしい言い回しへ
- 提案ボタンの文言をもっと自然にする
- 初見でも押しやすくする

### 6.3 AgentDeck

役割:

- 声を選ぶ
- 委ねる
- 今の声を感じる

改善方針:

- 各エージェントの差を色以外でも出す
- 選択中の声を明確にする
- 横スクロールが気持ちよくなるようにする

### 6.4 AgentStatus

役割:

- 今だれに聞いているかを示す

改善方針:

- 表示文を各エージェントらしくする
- 未選択、選択中、委ねるで表情を変える

### 6.5 ChatBubble

役割:

- 会話の読みやすさ
- 声の違いの表現

改善方針:

- 長文でも読める行間
- エージェントごとの返信ヘッダー
- 会議メモ風の余白
- 他の声を聞く導線を自然にする

### 6.6 InputComposer

役割:

- アプリで最も触る場所

改善方針:

- 入力中の安心感
- キーボード表示時の安定
- 送信ボタンの状態差
- placeholder文言の自然化

### 6.7 SessionRecordCard

役割:

- 会議録を見返す

改善方針:

- 日付と件数を読みやすく
- タイトル編集の余地を残す
- 削除導線は誤タップしにくく

### 6.8 PersonaModal

役割:

- エージェントの理解

改善方針:

- 説明が長すぎない
- 「この声は何をしてくれるか」が先に分かる
- 深く見る情報は段階的にする

### 6.9 ConstellationMap

役割:

- 7人の関係性を直感で見せる

改善方針:

- 星座として美しい
- 小さい画面でも読める
- ただの飾りでなく、声の選択につながる

### 6.10 Toast

役割:

- ささやかなフィードバック

改善方針:

- 目立ちすぎない
- 読みやすい
- すぐ消えるが雑ではない

## 7. エージェント別UI人格

Phase 6Cで、各エージェントを「読まなくても違う」と感じられるようにします。

### 7.1 レイ

役割: 映す人 / 静かな鏡

UI人格:

- 透明感
- 余白
- 青紫の淡い光
- 静かな反射
- 直線より柔らかい円

選択時:

- ふっと明るくなる
- 大きく動かない
- 水面の反射のような光

### 7.2 ジョー

役割: 照らす人 / 火花

UI人格:

- 金色
- 火花
- 前に進む感覚
- 少し強い光
- でも押しつけすぎない

選択時:

- 小さく灯る
- 上方向へ少し浮く
- 返信ヘッダーに熱量がある

### 7.3 ミナ

役割: 包む人 / 安心

UI人格:

- やわらかいピンク/ローズ
- 丸いカード
- 呼吸する余白
- 包むような境界

選択時:

- 膨らむように明るくなる
- 角がさらに柔らかく見える

### 7.4 サトウ

役割: 現実へ戻す人 / 地面

UI人格:

- 深い赤/土色
- 重心
- しっかりした境界線
- 揺れを止める感じ

選択時:

- 下方向に重心が乗る
- 輪郭が少し強くなる

### 7.5 ケン

役割: 構造を見る人 / 整える

UI人格:

- 青/シアン
- 線
- グリッド感
- 整列
- 明晰さ

選択時:

- 線が通る
- カード内の情報が整って見える

### 7.6 フィオ

役割: 連れ出す人 / 風

UI人格:

- 緑/ミント
- 軽さ
- 少し斜めの動き
- 外へ開く感じ

選択時:

- 斜め上に軽く浮く
- 風が抜けるような余白

### 7.7 トム

役割: 壊す人 / 突破

UI人格:

- 紫/マゼンタ/ノイズ
- 少しエッジ
- 破線や不規則な光
- ただし怖くしすぎない

選択時:

- 少しだけノイズっぽく光る
- 形がわずかに崩れるような印象

### 7.8 委ねる

役割: 今出るべき声に任せる

UI人格:

- 7色の合流
- 円環
- 無限記号
- 特定の人格ではなく場そのもの

選択時:

- 複数色がゆっくり巡る
- 「誰かが出る」のではなく「場に任せる」感じ

## 8. モーション方針

Phase 6Dで磨きます。

### 8.1 原則

- 派手にしない
- 速すぎない
- ぬるすぎない
- 必ず意味のある動きにする

### 8.2 速度の目安

- 小さなhover/tap: 120〜180ms
- カード選択: 180〜260ms
- モーダル表示: 260〜360ms
- スプラッシュ遷移: 600〜900ms
- 背景呼吸: 8〜18秒

### 8.3 入れたい動き

- エージェント選択時の微細な浮き
- モーダルの静かな出現
- サイドバーの滑らかな開閉
- トーストの軽い出入り
- 返信表示時の柔らかい出現
- 背景の極小の呼吸

## 9. スマホ優先ルール

- 文字入力時にズームさせない
- 入力欄は常に主役
- エージェントデッキは親指で触れる
- モーダルは閉じやすい
- サイドバーは広すぎない
- 重要ボタンは44px前後のタップ領域を確保
- 小画面では説明を減らす

## 10. やらないこと

Phase 6のUI/UX磨き込み中は、以下をやりません。

- 外部AI接続
- 認証
- クラウド同期
- 課金
- 本流じぶん会議との統合
- 大規模なフレームワーク移行
- エージェント人格定義の根本変更
- 重すぎるアニメーション
- 見た目だけで意味のない演出

## 11. Phase 6の実装順

### Phase 6A: World-class UI/UX設計固定

この文書を追加し、READMEから参照できるようにします。

### Phase 6B: デザインシステムとコンポーネント整理

- 共通トークン整理
- ボタン/カード/モーダル/トーストのルール化
- Phase別CSSの依存を見直す
- ただし大規模破壊はしない

### Phase 6C: エージェント人格UI化

- エージェントごとの選択状態
- AgentStatus文言
- PersonaModalの見え方
- ChatBubbleのアクセント

### Phase 6D: モーションと触感

- 選択/出現/閉じる/送信の動きを磨く
- reduced-motionを守る
- 重くしない

### Phase 6E: 実機最終調整

- Cloudflare公開URLをスマホで確認
- スクリーンショットを見ながら調整
- 小画面の崩れ修正
- READMEへ公開URLを追記するか判断

## 12. 完了条件

Phase 6全体の完了条件:

- 初見で何をするアプリか分かる
- 7人の声の違いがUIから伝わる
- スマホで毎日触れる軽さがある
- モーダル、サイドバー、入力欄が破綻しない
- 会議録として見返したくなる
- 見た目の美しさと使いやすさが両立している
- 余計な機能追加で複雑化していない

## 13. 判断基準

迷ったときは、以下を優先します。

1. 使いやすさ
2. 読みやすさ
3. じぶん会議らしさ
4. 美しさ
5. 実装の安全性
6. 将来の拡張性

美しさは大事ですが、使いにくくなるなら採用しません。
