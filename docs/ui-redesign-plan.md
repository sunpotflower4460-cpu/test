# じぶん会議 test版 UI redesign plan

## 0. この文書の目的

この文書は、`sunpotflower4460-cpu/test` リポジトリを「じぶん会議 test版 / 軽量UI実験版」として育てるためのUI設計固定メモです。

Phase 0では、挙動を大きく変えず、今後のUI改善方針・触る範囲・触らない範囲・手動ゲートを明確にします。

## 1. この版の位置づけ

このリポジトリは、本流のじぶん会議とは別に、以下の価値を磨く場所です。

- 軽く開ける
- スマホで気持ちよく触れる
- 初見でも何をするアプリか分かる
- エージェントの違いが直感的に伝わる
- ただのチャットではなく「自分の内側の会議」に見える

本流が深層OS・内部構造・エージェント自然化を担うなら、このtest版は「手のひらの中の静かな会議室」として育てます。

## 2. UIコンセプト

> 静かな夜の会議室に、自分の中の声が灯っていく。

見た目は派手にしすぎず、以下を大切にします。

- 余白
- 呼吸感
- 淡い発光
- ガラス感
- 手帳のような記録感
- スマホアプリらしい押し心地
- エージェントごとの色と気配

## 3. デザインテーマ

### Theme A: 夜の泉

主にダークモードで使うテーマです。

- 深い紺〜黒の背景
- 紫、青、金、緑の淡い光
- ガラス、霧、呼吸する光
- 静かで内省的な雰囲気

### Theme B: 朝の紙

主にライトモードで使うテーマです。

- 生成り、白、淡いベージュ
- やわらかい影
- 紙や日記のような安心感

### Theme C: 星座会議

エージェント選択や関係性マップで使う補助テーマです。

- 小さな点
- 線
- 中心に「あなた」
- 7つの声が周囲にある構図

## 4. Phase計画

### Phase 0: 設計固定

目的:

- test版の位置づけを固定する
- Cloudflare手動デプロイ前提にする
- UI改善方針を文書化する
- 今後の変更範囲と手動ゲートを明確にする

変更範囲:

- `README.md`
- `docs/ui-redesign-plan.md`

触らない:

- アプリ挙動
- 会話生成ロジック
- エージェント思想
- 外部API
- 認証
- DB

### Phase 1: UI土台の大幅強化

目的:

- 第一印象を大きく上げる
- スマホアプリらしい見た目にする
- 既存機能を壊さず、CSS中心で改善する

対象:

- スプラッシュ画面
- 背景
- 空チャット画面
- 入力欄
- ボタン
- safe-area対応
- READMEの補足

主な変更候補:

- 背景グラデーションを多層化
- 呼吸する光の粒を追加
- 空チャットを「今日の会議室」風にする
- 入力欄をガラス風パネルにする
- ボタンの押し心地を改善
- モバイル下部の余白を調整

完了条件:

- スマホで見てアプリらしく感じる
- 既存のオンボーディング、スプラッシュ、チャット送信、エージェント選択、テーマ切替が壊れない
- secretやAPI keyを追加しない

### Phase 2: エージェント体験の強化

目的:

- 誰に話しているか分かりやすくする
- エージェントの違いを見た目で伝える
- 「ランダム」を「委ねる」体験へ寄せる

対象:

- エージェントバー
- 選択状態
- 入力欄上の状態表示
- ペルソナモーダル

主な変更候補:

- エージェントバーを「声のデッキ」化
- `ランダム` 表記を `委ねる` に寄せる
- 選択中エージェントを少し浮かせる
- 入力欄付近に「レイに聞いています」「委ねています」などを表示
- プロフィールモーダルを短く読みやすく再構成

### Phase 3: 会議感・記録感の強化

目的:

- ただのチャットではなく「内面の会議」に見せる
- 戻って見返したくなる記録にする

対象:

- チャットバブル
- セッション一覧
- 関係性マップ
- 会議録UI

主な変更候補:

- `セッション` を `会議録` に寄せる
- セッション一覧をカード化
- 返信バブルに薄い光の縦線を入れる
- 関係性マップを星座風にする
- 「他の声も聞く」導線の見た目を追加

### Phase 4: Cloudflare手動デプロイ整備

目的:

- Vercelを使わない運用に合わせる
- Cloudflare Pagesで手動デプロイしやすい説明を整える

対象:

- README
- 必要なら補助ドキュメント

方針:

- Build commandは不要または空欄
- Output directoryはルート想定
- secret不要
- 本番公開判断は手動ゲート

## 5. 初期UI改善の優先順位

1. スプラッシュと背景を美しくする
2. 空チャット画面を「今日の会議室」にする
3. 入力欄をスマホアプリ品質にする
4. エージェントバーを声のデッキにする
5. プロフィールモーダルを見やすくする
6. 関係性マップを星座化する
7. 会議録サイドバーを整える

## 6. 安全ルール

以下は絶対に守ります。

- API key / token / secret をコードに書かない
- `.env` をコミットしない
- 外部API接続はPhase 0〜Phase 1では行わない
- 認証・DB・課金は触らない
- 大規模リファクタは別Phaseで明示してから行う
- 中核思想・人格定義の大幅変更は手動確認を挟む

## 7. PRレビュー観点

毎回のPRで確認すること:

- 変更範囲がPhase目的に収まっているか
- secretやAPI keyが入っていないか
- 既存機能が壊れていないか
- スマホ表示が大きく崩れていないか
- Cloudflare手動デプロイ前提と矛盾していないか
- 本流じぶん会議と混同するような記述になっていないか

## 8. Phase 1への引き継ぎ

Phase 1では、まずCSS中心で見た目を強化します。

最初の実装候補:

- `body` 背景の多層グラデーション
- `#splash-screen` の入口体験強化
- `#welcome-prompt` のカード化
- `#input-area` のガラス風固定パネル化
- `.welcome-suggestion-btn` の押し心地改善
- モバイル下部safe-areaの調整

この段階では、`js/chat.js`、`js/agents.js`、`js/modes.js` は触りません。
